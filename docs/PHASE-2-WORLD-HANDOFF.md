# Phase 2 live world handoff

The live app now lists seven arcade activities and nine map destinations. Original vector panoramas in `RoomScenery` illustrate Downtown Plaza, Wonder Park Entrance, Carnival Midway, and Club Pulse; the same art supplies map/destination previews. Existing licensed artwork and fonts stay local. The room manifest artwork strings describe scene layers and are never requested as missing image files.

`PLACES` remains the destination/save-validation owner. `ROOM_MANIFESTS` selects the four panoramic rooms. The existing save key and V1/V2 formats retain compatibility: new visited IDs survive restoration; current room and foot position are session state and reload at Savanna Square. App navigation passes portal arrival positions into the newly mounted World, preventing the prior room's coordinates from activating destination portals.

`CameraViewport` owns the viewport-sized ground, logical stage scale, clamped follow camera, pointer conversion, and portal latch. Pointer input adds the camera offset once after dividing by the stage scale. Movement projects outside clicks onto the walkable polygon; keyboard movement reaches physical edge portals. Panorama movement applies its foot position directly, so camera, avatar, footfalls, and trails share the same drawn coordinates. The avatar name and pet sit outside the avatar's foot anchor. Board movement uses the same 1.5× keyboard step as the legacy world. Mango canvas backing dimensions use logical CSS pixels before the camera scales the scene.

Room paths and activities also have named controls below the canvas. Spatial hotspot controls support pointer input and defer keyboard access to that strip. Dance tiles remain keyboard buttons: focus follows their tile position into the camera, and presses move the avatar to the tile center. The camera uses clipping rather than an independently scrollable stage. Reduced motion freezes ambient ride motion, floor pulses, avatar transitions, and board sparkles while retaining controls and scoring.

App's Games Dialog is the sole modal owner for all seven activities. The Games header opens the menu; café Blend smoothies, Club Pulse DJ Booth, park Ride Savanna Screamer, and midway Fruit Catch triggers select their activity immediately. GamesPanel preserves All games focus restoration. SmoothieKitchenContent is embeddable; SmoothieKitchen retains its standalone fixture wrapper and recipe subtitle. Dialog captures the opener before game effects focus their controls and falls back to the current ground if navigation removed the opener. Native modal inertness protects world movement behind games.

DJ rewards call `completeDJBeatDrop` with score/combo rather than trusting UI coin totals. Café servings call `completeSmoothieOrder`. Coaster semantics follow `COASTER-HANDOFF.md`: no coins, no played-game increment, no persisted photo, and a local view/download souvenir on natural completion. Ferris wheel, flume, teacups, and carousel remain spectator scenery. Their available controls say Watch; the supported midway booth launches Fruit Catch. Fountain and map kiosk controls provide their real described behavior. No speculative minigame or service was added.

Validation: the original RED run failed the new visit/pointer/polygon cases, then the final unit suite passed 165 tests. New `tests/world-phase2.spec.ts` covers real map/path/physical portal navigation and safe spawns, scaled camera click accuracy, exact avatar/tile alignment and off-camera tile focus, saved DJ/smoothie rewards, one modal, inert world input, direct/arcade launches, Escape/focus, reduced motion, overflow, accessibility, hoverboard trail alignment, and logical mango canvas sizing. These browser regressions are authored for the integration gate; the implementer did not run the full browser suite, typecheck, or build.

Manual Chromium render probes at 1440×1000 and 390×844 loaded the real world, launched the real DJ and café bodies, and closed them with Escape. Both reported zero page errors, zero HTTP responses at 400 or above, exactly one open activity dialog, restored opener focus, and no document overflow. Mobile avatar/tile center and baseline differences were less than 0.001px.
