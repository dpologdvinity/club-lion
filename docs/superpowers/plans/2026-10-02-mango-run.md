# Mango Run Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add "Mango Run" endless steering minigame (3 lives, score = distance + mangoes*10, repeatable rewards) to Club Lion arcade.

**Architecture:** DOM sprites (positioned elements) in new `src/components/MangoRun.tsx`, extend `game.ts` with `mangoRunBest` and `completeMangoRun`, update Games panel to be a picker (Memory Safari | Mango Run), add minimal styles in `src/styles.css`. Follow existing patterns (MemorySafari states, onFinish/onClose).

**Tech Stack:** React + TypeScript + Vite, CSS design tokens, requestAnimationFrame, DOM events.

**Spec:** docs/superpowers/specs/2026-10-02-mango-run-design.md

## Global Constraints

- Single-player, local-only. No network calls.
- Versioned localStorage save (Player.version 1). Restore tolerant of missing fields.
- DOM-first, accessible, respect `prefers-reduced-motion: reduce`.
- Follow existing code style (Prettier defaults: 2-space indent, double quotes, semicolons). TypeScript strict.
- No speculative features. YAGNI. TDD.

## Review Focus

- Save backward compatibility: restorePlayer with saves missing `mangoRunBest` must not corrupt state.
- Collision fairness: spawning must not create unavoidable immediate hits (minimum gap from lion).
- Reward semantics: repeatable coins, score >=0, gamesPlayed increments each completion.
- Keyboard focus: game area focusable for keyboard-only play; movement doesn't leak to chat/inputs.
- Reduced motion: animations disabled without breaking gameplay loop.
